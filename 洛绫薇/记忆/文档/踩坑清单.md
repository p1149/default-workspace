> 2026-11-01 14:3x 主人令「**学习 避免踩一样的坑**」→ 把反复出现的坑列成清单，并给每个坑配一条**机制**（脚本检查 / 固定动作），不只靠记性。
> 位置：`洛绫薇的记忆/文档/踩坑清单.md`。新坑出现就往下加，加完同步给 `第二法则.md`「技能与教训」一句摘要。

## 一、已经踩过 ≥2 次的坑（重点）

### 坑 1 · 编辑 `.ps1` 会丢 UTF-8 BOM（已踩 4 次）

- **现象**：用编辑工具改完 `.ps1`，文件开头 3 字节 BOM 消失 → PowerShell 5.1 按 ANSI(GBK) 解中文 → 满屏「意外的标记」「字符串缺少终止符」等**假语法错**，文件其实没坏。
- **为什么危险**：容易被判成「我把脚本改坏了」，于是回滚或重写，浪费一轮；也可能真的去「修」一个没坏的脚本。
- **案例**：`合并md到记忆.ps1`（14:30）、`对账.ps1`（14:34）、10-30 的 `dsh-watchdog` 等。
- **防复发（已落地）**：① `tools\对账.ps1` 第 6 项 = **脚本编码检查**，扫 `tools\*.ps1`：含中文的必须有 BOM、`ParseFile` 必须 0 错；② 改完 `.ps1` 固定跑一遍补 BOM + 语法复核（3 行代码）。
- **标准修法**：`[IO.File]::WriteAllBytes($p, [byte[]](0xEF,0xBB,0xBF) + $b)`，然后用 `[Parser]::ParseFile` 复核。

### 坑 2 · `edit` 的 `old_string` 切在长段落中间 → 尾部被复制一份（已踩 2 次）

- **现象**：想在某条长列表项前插新条目，只截了行首一段做锚点，结果旧条目**后半截留在原地**，同一条内容出现两遍（实测重复 547 字符）。
- **防复发**：`old_string` 要么**取到行尾**，要么整行替换；改完立刻核对行数 / 字符数 / 匹配次数（`grep` 数一遍原句）。

### 坑 3 · `对账.ps1` 结尾带 `exit` → 同一条命令里后续语句不执行（已踩 2 次）

- **现象**：`& $sb; "后续输出"` —— 后续那行永远不打印，让人以为命令没生效。
- **防复发**：**一条命令只跑一个带 exit 的脚本**；要连着做别的事，拆成两次调用。

### 坑 4 · 用「日志里搜关键词」判断消息是否送达（已踩 1 次，差点误报）

- **现象**：搜到的是自己写在指令里的示范句，不是对方真的收到。
- **防复发**：解压会话日志**按 role 看 assistant 消息**；或用接口返回码 + 对方回执双证。

## 二、只踩过一次但要记住的

| 坑 | 教训 |
|---|---|
| `$cands[0]` 在只剩一个元素时 PowerShell 把数组降成字符串，取到首字母 | 用 `foreach` 或 `@()` 包一层 |
| PS 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM，JSON/YAML 解析失败 | 写配置文件用 `UTF8Encoding($false)` |
| `session.v4.jsonl.zstd` 是多帧拼接，`zstdDecompressSync` 只解第一帧 | 按 magic `28 B5 2F FD` 切帧逐段解 |
| 重启后宿主 cwd 不是工作区（`~\ .dsh\profiles\desktop`），cwd 校验把真实工作区也挡成 400 | 校验要多根：进程 cwd + 插件所在工作区 + 环境变量 |
| `Get-Content` 的 `.Count` 与真实行数偶尔对不上（实测报 25，实际 61 行） | 数行用 `[IO.File]::ReadAllLines()`，别用 `Get-Content .Count` 下结论 |
| `robocopy /MOVE /E` **跟随符号链接**（pnpm 的 `node_modules` 全是链接）→ 递归复制、体积爆炸（实测 2.3 GB → 59 GB、跑 2 小时 49 分被系统 kill、路径超长） | 跨盘搬 `node_modules` 必须 `/XJ /SL`（排除 junction、复制链接本身），或**先删 node_modules**（可 `pnpm install` 重建）；大搬移前先拿小目录试一次 |
| 用 `robocopy 空目录 /MIR` 清理目标，**没先确认目标不是唯一副本** → 删光 13 个顶层项（含 `.agents` 3,953 文件）+ `apps/cli`、`packages`、`docs`、`scripts` 等大量内部文件 | `/MIR` 是**删除镜**不是清理工具；用它前必须确认别处有完整副本；**被 kill 的 `/MOVE` 不能凭「源目录看起来空」判定搬完**，要用 `robocopy /L` 差异扫描或事先做完整性清单 |
| profile 的 `package.json` / `pnpm-lock.yaml` / `bundles` 三者会漂移（删插件只改前两者） | **动 `pnpm install` 前先跑 `tools\备份profile依赖.ps1`**：备份 + 一致性检查 + 确认 `session-briefing` 三处都在；本机现状 = lock 多 `@local/bili-qr-sidebar` 一条（install 会清掉，属预期） |
| 记忆「第二部分」把 archive 全文抄一遍 → 体积虚高 682 KB | 2026-11-01 已修：刷新排除 archive，备份只留 10 份 |

## 三、每条坑的固定动作（背下来）

1. 改 `.ps1` → 补 BOM → `ParseFile` 0 错 → 再跑。
2. 改长列表 → `old_string` 取到行尾 → 改完数匹配次数与行数。
3. 跑 `对账.ps1` → 单独一条命令 → 看 `结果:` 行与退出码。
4. 说「已送达」→ 必须有接口返回码 **或** 对方回执，两者其一。
5. 说「已验证」→ 附真实输出 / 退出码 / 路径，不空说。

## 四、机制层（不靠记性的那道保险）

- `tools\对账.ps1` **第 6 项**：脚本编码与语法（2026-11-01 新增，实测 **21 个 .ps1 全部合规**；自测过「无 BOM + 中文」会被判不合规）。
- 对账现在是 **6 项**：归档 INDEX / 记忆最近归档 / 健康摘要（已停用） / 会话索引 / 任务看板 / 脚本编码。
- `tools\备份profile依赖.ps1`（2026-11-01 新增）：备份 profile 的 package.json / pnpm-lock / cordis.patch，导出 `node_modules\@local` 链接，输出 manifest vs lock vs bundles 差异；**退出码 1 = 有不一致**（有差异不等于坏了，先看差在哪）。
- 每轮收尾必跑；FAIL 不清零不收工。
