# 场景索引（共享层）

> 依据 `框架/规则.md` 第一条「场景主权」建立：每个场景只拥有、只读写自己的记忆；不得跨场景读取或修改其他场景的记忆。

## 一、标准场景结构（所有场景 = 项目）

每个场景一个目录，内含六文件 + 可选归档：

| 组件 | 文件 | 性质 | 说明 |
|---|---|---|---|
| 定位卡 | `定位卡.md` | 静态 | 负责什么 / 工作流 / 边界 |
| 身份卡 | `身份卡.md` | 静态 | 场景名 / 类型 / 一句话 |
| 场景画像 | `画像.md` | 动态 | 特征 / 习惯 / 模式，随「自动归纳」更新 |
| 私有记忆 | `记忆.md` | 动态 | 当前状态 / 关键事实 / 待办 |
| 项目记忆 | `项目记忆.md` | 动态 | 项目变化 → 归纳沉淀 |
| 私有技能 | `技能.md` | 半静态 | 本场景私有技能清单 |
| 交接归档 | `框架/archive/` | 按需 | 每三轮交接记录（可选） |

## 二、隔离规则

- 洛绫薇在某个场景内，只读写该场景自己的六文件（`定位卡.md` / `身份卡.md` / `画像.md` / `记忆.md` / `项目记忆.md` / `技能.md`）及 `框架/archive/`。
- 全局层对所有场景可读：`框架/洛绫薇.md`、`框架/第二法则.md`、`框架/规则.md`、本索引；修改权按「修改权分层」。
- **禁止**跨场景读取或修改其他场景的任何文件。

## 三、自动归纳（提炼）流程

1. 场景会话（一轮或多轮）结束后，读取该场景 `记忆.md` + `画像.md`，提炼「候选归纳」（特征变化 / 新习惯 / 可沉淀结论）。
2. 候选**不自动写**，先呈主人确认。
3. 主人确认后，写入该场景 `画像.md`，并更新 `记忆.md` 的「最近归档」。
