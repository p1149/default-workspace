## 会话轮转机制（2026-10-30 07:35）
- **需求**（主人原话）：轮数保持 1 轮、步数 ≤10；超过 10 步的会话自动新建会话继续运行；达到 10 步的会话在任务之后清空，清空前把「当前状态」按执行顺序写进 `记忆.md`。
- **调查结论**：
  - DSH 引擎**没有**内置轮次/步数预算（`packages/core/agent-loop/README.md:220` 明说），必须从生命周期扩展点实现。
  - 可挂点：`agent/pre-step` waterfall（payload 带 `turn`/`step`，返回 `{kind:'reject'}` 关闭本轮且不花该步，`agent-loop/src/agent.ts:340`）。
  - 续跑：`ctx.agents.create({sessionId, meta:{cwd}, agentOptions, setup})` + `agent.followup(message)`（`core/agent/src/index.ts:416`、`runtime-types.ts:251`）。
  - **没有**删除/清空会话的 API（持久化 seam 只有 create/open/flush/stat/list；`SessionStartSource` 的 `clear` 无发出方）。所以「清空」= 写回状态后不再续用，由新会话承接；旧日志仍在 `~/.dsh/sessions`。
  - GUI 没有「清空轮次与步」功能；最接近的是 fork 与 archiveSession。
- **实现**：工作区新插件 `session-rotation/`（纯 host、零 @deepseek-ai 依赖）：
  - `apply()` 内注册 `agent/pre-step`（超限：写记忆 → 新建会话 → followup 承接 → reject）与 `session/event` 的 `turn/end`（任务结束存档）。
  - 记忆写入：插到 `## 当前状态（最近一次会话）` 小节末尾，按执行顺序追加。
  - 新会话沿用 `ctx.agentDefaultModel.currentSelection()` + `ctx.agentPresets`（默认 preset 挂载）。
  - 安全兜底：新会话创建失败 → 不轮转、本轮继续（不中断任务）。
- **验证**：`node --check index.js` 通过；`node test\rotation.test.mjs` 全过（超限轮转/放行/存档顺序）；把包装进 web profile 后 `dsh web` 启动，插件在真实 Cordis 宿主 apply（`.loaded` 刷新为 pid=8856 07:33:57）且无报错；web profile 已还原备份。
- **安装状态**：desktop profile `package.json` 已加 `@local/session-rotation`（link）+ bundles 末位；因担心 HMR 热激活打断当前会话，在 profile `cordis.patch.yml` 末尾加了临时 `disabled: true`。**重启 DSH 后删掉该行即生效**。
