# 场景 · 执行 / 审计支撑规范

> 回答两个问题：**场景的活怎么执行（执行支撑）**、**干完怎么验（审计支撑）**。
> 核心：一切以「真实项目」为事实源头，证据可追、回执可查。

## 一、执行支撑（怎么干）

| 步骤 | 动作 | 支撑 |
|---|---|---|
| 1. 进入场景 | 读本场景 `记忆.md`（场景指针） | `私有记忆规范.md` |
| 2. 定位项目 | 指针 → 项目记忆 → 真实项目 | `写回链规范.md` |
| 3. 干活 | 在真实项目里做（README / 项目信息 / 产物） | 场景技能 |
| 4. 留证据 | 真实输出 / 退出码 / diff / 日志 / 截图 / 路径 | `框架/规则.md` 第五条（证据回执） |
| 5. 更新指针 | `记忆.md` 的 状态 / 下一步 | 洛绫薇维护 |
| 6. 归纳候选 | 工具收集 → 洛绫薇提炼候选 | `tools/归纳候选.ps1` |
| 7. owner 确认 | 主人点头（闸门，别人不能代签） | `写回链规范.md` |
| 8. 写回 | 项目记忆 7 字段 + 确认候选 | `写回链规范.md` |

### 执行铁律
1. **不空说「应该可以」**——必须给真实输出、退出码、路径；
2. **不越场景**——只读写本场景的六文件；
3. **不跳过闸门**——没 owner 点头不写项目记忆。

## 二、审计支撑（怎么验）

| # | 检查项 | 通过标准 | 工具 |
|---|---|---|---|
| 1 | 文件齐全 | 六文件都在 | `tools/审计场景.ps1` |
| 2 | 身份卡 | 有 卡指纹 / 会话 / 布局 | 同上 |
| 3 | 私有记忆 | 身份锚 + 场景指针 | 同上 |
| 4 | 项目记忆 | 7 字段摘要 + 确认候选 | 同上 |
| 5 | 定位卡 | 主人已填（无「【主人填写】」占位） | 同上 |
| 6 | 证据链 | 证据 → 事实源头可追 | 人工 |
| 7 | 写回 | 有 owner 确认记录 | 人工 |

## 三、证据链（审计核心）

```
真实项目（事实源头）
   ↓ 留证据
证据（日志 / 输出 / diff / 截图 / 路径）
   ↓ 回执
回执（谁确认、何时、结果）
   ↓ 写回
项目记忆（7 字段摘要 + 确认候选）
```

**审计就是倒着查这条链**：项目记忆 7 字段 → 回执 → 证据 → 真实项目，能不落地地走通 = 通过。

## 四、审计节奏

| 时机 | 审计范围 |
|---|---|
| 每个项目完成 | 该项目所在场景 |
| 场景分发 / 迁移后 | 全部场景 |
| 主人要求 | 指定场景 |

## 五、工具

```powershell
# 审计单个场景
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\审计场景.ps1 -Scene 自我复盘

# 审计全部场景
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\审计场景.ps1 -All
```
