## 一、为什么要有对账

今天（2026-10-30）实测对账出 4 处不一致：

| # | 对象 | 发现问题 |
|---|---|---|
| 1 | 归档 | `INDEX.md` 止于 15:14，实际 117 条交接（25+ 条未入） |
| 2 | 健康摘要 | 最后心跳 06:57（4.5 小时前），仍写「命令台故障待处置」而根因已定位 |
| 3 | 记忆 | 「最近归档」落后实际最新一条 |
| 4 | 会话索引 | 头部自报 32 个 / 表内 48 行 / 记忆写 30 个 / 实际 37 个文件 |

结论：**写了 ≠ 对过**。对账 = 把「写完」变成「核对过」。

## 二、何时对

1. **每轮收尾**（写完交接后，约 3 分钟固定动作）；
2. **心跳巡检时**顺带（每小时）；
3. 改动共享层文件（记忆 / 看板 / 健康 / 索引）之后必对。

## 三、对什么（五对）

| # | 对象 | 查什么 | 修法 |
|---|---|---|---|
| 1 | **归档** | `archive/INDEX.md` 条数 = 实际交接文件数 | `tools/对账.ps1 -Fix` 重建 |
| 2 | **记忆** | `记忆.md`「最近归档」= 最新**写盘**那条 | 人工改正 |
| 3 | **健康摘要** | 最后心跳 / 补记 < 2 小时；过时结论改口径 | 补记或改口径 |
| 4 | **会话索引** | 头部条数 = 实际会话文件数；绑定会话有效 | 重算头部 |
| 5 | **任务看板** | 待办未销单 ≤ 5；回执与销单对齐 | 对账销单 |

## 四、工具

| 命令 | 作用 |
|---|---|
| `.\tools\对账.ps1` | 只读检查五项，输出 PASS / FAIL，退出码 0 = 全过 |
| `.\tools\对账.ps1 -Fix` | 额外重建 `archive/INDEX.md`（机械项自动修） |

## 五、红线

1. 对账**只报告 + 修机械项**（INDEX 重建）；**不改事实内容**（记忆结论 / 看板条目 / 健康结论要人工判断）。
2. 对账发现的问题**写进交接**，不静默吞掉。
3. 对账不替代「执行审计规范」——审计查行为，对账查文档一致性。
4. **问题上交洛绫薇判断**（2026-10-30 16:49 主人令）：对账 / 审计 / 巡检发现的**任何异常**，第一时间**报洛绫薇判断处置**——不静默处理、不让其他场景代判；洛绫薇判断后**能自行处置的自行处置并留证**，**需主人拍板的再上报**。
