# 洛绫薇 · 会话开场简报（session-briefing）

> **2026-10-31 01:20 主人令：会话开场简报写入「底层」。**
> 运行层组件：`session-briefing/`（@local Host 插件，已装 desktop profile，已生效）。

## 一、是什么
每个会话在**第一次准备步骤**时，自动往请求消息末尾注入一条 **user 上下文**
（`source.kind = "session-briefing"`、`form = "snapshot"`），内容是从工作区**现读现拼**的 6 块简报，
真实输出约 **1.5k 字符**（≈ 600–800 token），`maxChars` 可调。

## 二、6 块内容（来源）
| 块 | 来源 | 说明 |
|---|---|---|
| 全局须知（原话） | `框架/共享/参考.md` → 一、全局须知 | 只认主人与洛绫薇原话 |
| 场景与归档 | `框架/共享/场景索引.md` + `框架/场景/` + `框架/archive/` 最新 | 场景清单 + 最新交接归档 |
| 任务看板 | `框架/共享/任务看板.md` | 待办 + 最近 2 条回执 + 通知 |
| 健康摘要·待关注 | `框架/共享/健康摘要.md` | 只带「待关注」 |
| 记忆·当前状态 | `框架/洛绫薇的记忆.md` → 当前状态 | 快照，不读全量 |
| 开场必读顺序 | 固定文案 | 法则 → 规则 → 记忆 → 参考 → 看板 → 健康 → 最新归档 |

## 三、机制（照 DSH 官方 `time-context`）
- `ctx.on('agent/pre-step', async (payload, next) => ..., { prepend: true })` → **首次准备时注入**；
- 消息由插件自造：`{ id, role:'user', content:[{type:'text',text}], source:{kind:'session-briefing', form:'snapshot', sections:[{name,text}]} }`；
- **去重**：会话历史里已有 `source.kind === 'session-briefing'` 的 user/message 即视为已开场（内存 Set 快路径）；
- **豁免**：子代理会话（`origin === 'subagent'` 或 `delegationDepth > 0`）不注入；`cwd` 不在 `workspace` 内不注入；
- **fail-open**：读文件 / 组装 / 注入失败只写 stderr（warn），原样返回决策，不阻断会话；全空则不注入。

## 四、配置（`cordis.patch.yml` 里生效）
| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | `false` = 不注册监听 |
| `workspace` | 插件目录上一级 | 只对这一目录下的主会话注入 |
| `maxChars` | `2400` | 简报总字符上限（超出按节截断） |
| `boardReceipts` | `2` | 带几条最近完成回执 |
| `sceneChars` / `boardChars` / `healthChars` / `memoryChars` / `referenceChars` | 240 / 700 / 320 / 700 / 320 | 各节独立上限 |
| `files.*` | 见 `index.js` DEFAULTS | 各简报来源文件（相对 workspace） |

## 五、边界（红线）
- **不改**会话历史、**不删**消息、**不碰** profile；
- 只对 workspace 内主会话注入**一次**；
- 简报内容**只读**，不写入任何文件。

## 六、与法则 / 规则的关系
- 简报**不替代**开场必读顺序（法则 → 规则 → 记忆 → 参考 → 看板 → 健康 → 最新归档）——它只是「摘要 + 提醒」，细节仍须按顺序读；
- `规则.md` 第六条「开场必读」由简报**自动化为第一步**（但读法不变）。
